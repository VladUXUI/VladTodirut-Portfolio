<SectionTitle eyebrow="Design Systems">How I build design systems now</SectionTitle>

I've done design systems a few different ways over the years. I built one from scratch at Taho, used Uber's at Mezo, and spent most of my time at Peanut cleaning one up. This is how I do it now, and where each part of it came from.

<SectionTitle eyebrow="01" id="brand">It starts with the brand</SectionTitle>

Before any tokens or components, I start from the brand. The colours, type and shapes should come from what the product is.

I learned that one at Mezo. We used Uber's design system, which got us going faster, but it came with a bigger learning curve, and it wasn't really built for crypto. Crypto has some specific needs, and we kept having to work around them with components that were made for something else.

<SectionTitle eyebrow="02" id="tokens">Tokens, then a couple of real pages</SectionTitle>

I set up the tokens in Figma with AI: colour, type, spacing, radius. Then I design one or two pages by hand, using only those tokens. That's the part I don't hand over, because that's where most of the design decisions get made. Once the pages feel right, AI helps me pull the repeating bits out into components and patterns.

At Taho I did all of this by hand. I was the only product designer, so I built the whole system from scratch in Figma, then reviewed each component once the developers had built it. It worked (Taho grew to around 150,000 active users), but it was time consuming, lengthy and very repetitive. [Read the Taho case study →](/work/taho)

<SectionTitle eyebrow="03" id="code">Getting it into code</SectionTitle>

Next, the tokens and components go into code, again with AI, and I check that they match Figma.

TokenFoundry came out of this step. Earlier this year, AI kept drifting when it turned designs into code, so I built a Figma plugin and a preview site that turn design tokens into a React + Tailwind design system. It meant less drift and less back and forth. The tools have caught up since, so I don't really need it anymore, but I still start from tokens.

<SectionTitle eyebrow="04" id="docs">Docs, and keeping an eye on it</SectionTitle>

Every system gets a documentation website with the design resources and the code, plus a `DesignSystem.md` file. I also check how much the system is actually used, and by who.

That part comes from Peanut, a fintech app with a crypto component. When I joined as their designer, they already had a style and a design system, which was a nice head start. But it had drifted a lot: components used for things they weren't meant for, lots of versions of the same thing, and plenty of accessibility issues. Most of my time went into wrangling all of it and cleaning it up.

I used AI to audit the app and build a small website to show the team where the drift was. Then I rebuilt the components and the docs in Figma, and we agreed when to use modals, drawers and notifications.
